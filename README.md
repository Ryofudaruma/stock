# 株価下落通知ツール

登録した日本株・米国株の株価を **30分おき** にチェックし、あらかじめ決めた金額(閾値)**以下** になったら **LINE** と **メール** でお知らせするツールです。

GitHub Actions(GitHub が無料で提供している自動実行の仕組み)の上で動くため、**自分のパソコンを起動しておく必要はありません**。

## 1. しくみの概要

- `config.yaml` に書いた銘柄の現在値を、30分おきに Yahoo Finance から取得します。
- 現在値が閾値 **以下** なら、LINE に通知します。
  - LINE の送信に失敗したときは、代わりにメールで通知します(設定で「常にメールも送る」にもできます)。
- 同じ銘柄について、**同じ日(日本時間)に何度も通知はしません**。
  - ただし、一度閾値を上回ってから再び下回った場合は、改めて通知します。
- 「今日どの銘柄を通知済みか」は `state.json` に記録され、GitHub Actions が自動でコミットします。**このファイルは手で編集しなくて大丈夫です。**

通知の例:

```
【株価アラート】トヨタ自動車(7203.T)
現在値: 2450.0
設定した閾値: 2500 を下回りました。
```

## 2. GitHub にリポジトリを作成してファイルを置く

### 2-1. GitHub アカウントを用意する

まだ持っていない場合は <https://github.com/signup> から無料アカウントを作成してください。

### 2-2. リポジトリ(ファイルの置き場所)を作る

1. <https://github.com/new> を開きます。
2. **Repository name** に好きな名前(例: `stock-alert`)を入力します。
3. 公開範囲を選びます。
   - **Private(非公開)を推奨** します。Public にすると、監視している銘柄や閾値が誰でも見られる状態になります。
   - Private の場合、GitHub Actions の無料枠は月 2,000 分です。このツールは 30 分おき実行で月およそ 1,500 分前後を使う見込みです(詳しくは「[8. 注意事項](#8-注意事項既知の制約)」)。
4. 「Add a README file」などのチェックは **付けずに**、**Create repository** を押します。

### 2-3. このフォルダのファイルをアップロードする

**方法A: git コマンドを使う(おすすめ)**

パソコンに [Git](https://git-scm.com/downloads) をインストールし、このフォルダ(`README.md` がある場所)でターミナル(Windows なら「PowerShell」、Mac なら「ターミナル」)を開いて、以下を実行します。
`<あなたのユーザー名>` と `<リポジトリ名>` は自分のものに置き換えてください。

```bash
git init
git add .
git commit -m "初回コミット"
git branch -M main
git remote add origin https://github.com/<あなたのユーザー名>/<リポジトリ名>.git
git push -u origin main
```

**方法B: ブラウザからアップロードする**

1. 作成したリポジトリのページで **uploading an existing file** のリンクを押します。
2. このフォルダの中身をすべてドラッグ&ドロップして **Commit changes** を押します。
   - `.github` フォルダ(名前が `.` で始まるフォルダ)は、Mac の Finder や Windows のエクスプローラーで **非表示** になっていることがあります。必ず `.github/workflows/check.yml` もアップロードされていることを確認してください。
   - Mac の Finder では `Command + Shift + .` で隠しファイルを表示できます。

> **重要:** 定期実行は、リポジトリの **既定のブランチ(通常は `main`)** に置かれた `check.yml` だけが動きます。

## 3. LINE の設定(チャネルアクセストークンと userId の取得)

> 以前よく使われていた **LINE Notify は 2025年3月末でサービスを終了** しました。
> そのため本ツールは **LINE Messaging API**(LINE公式アカウント=ボットから自分にメッセージを送る方式)を使います。
> 自分専用のボットを1つ作り、そのボットから自分に通知が届くイメージです。

LINE の画面は変更されることがあります。ボタン名などが違う場合は、近い名前のものを探してください。

### 3-1. LINE 公式アカウント(ボット)を作成する

1. <https://developers.line.biz/console/> を開き、**LINEアカウントでログイン** します。
   - 初回は開発者として名前・メールアドレスの登録を求められるので入力します。
2. **プロバイダー** を作成します。
   - 「作成」または「Create a new provider」を押し、名前(例: `自分用ツール`)を入力して作成します。
3. 作成したプロバイダーを開き、**Messaging API** のチャネルを作成します。
   - 「Messaging API」を選ぶと「LINE公式アカウントを作成する」画面に案内されます。案内に従って LINE公式アカウント(例: 名前「株価アラート」)を作成してください。
   - 作成後、<https://manager.line.biz/> (LINE Official Account Manager)で作ったアカウントを開き、右上の **設定** → 左メニューの **Messaging API** → **Messaging APIを利用する** を押し、先ほど作ったプロバイダーを選択します。
4. もう一度 <https://developers.line.biz/console/> を開くと、プロバイダーの中にチャネル(例: 「株価アラート」)ができています。

### 3-2. 自分の userId を確認する

1. LINE Developers コンソールで作成したチャネルを開きます。
2. **チャネル基本設定**(Basic settings)タブを開きます。
3. ページ下の方にある **あなたのユーザーID**(Your user ID)の値をコピーします。
   - `U` から始まる 33 文字の文字列です(例: `U1234abcd...`)。
   - これが **`LINE_USER_ID`** になります。

### 3-3. チャネルアクセストークン(長期)を発行する

1. 同じチャネルの **Messaging API設定**(Messaging API)タブを開きます。
2. 一番下の **チャネルアクセストークン(長期)** の **発行** ボタンを押します。
3. 表示された長い文字列をコピーします。
   - これが **`LINE_CHANNEL_ACCESS_TOKEN`** になります。
   - **このトークンは他人に見せたり、ファイルに書いてアップロードしたりしないでください。**

### 3-4. ボットを友だち追加する(必須)

1. 同じ **Messaging API設定** タブにある **QRコード** を、スマホの LINE アプリで読み取ります。
2. ボットを **友だち追加** します。
   - **友だち追加していないと通知は届きません。**
3. (任意)LINE Official Account Manager の **設定 → 応答設定** で「応答メッセージ」をオフにすると、ボットに話しかけたときの自動返信が止まります。

## 4. Gmail のアプリパスワードを発行する

メール通知を使わない場合は、この手順は飛ばして、`config.yaml` の `email: false` にしてください。

アプリパスワードは、ツールが Gmail からメールを送るための「専用パスワード」です。普段の Google アカウントのパスワードは使いません。

1. Google アカウントで **2段階認証プロセス** を有効にします。
   - <https://myaccount.google.com/signinoptions/two-step-verification> を開き、案内に従って設定します(すでに有効なら不要)。
2. <https://myaccount.google.com/apppasswords> を開きます。
3. **アプリ名** に分かりやすい名前(例: `stock-alert`)を入力して **作成** を押します。
4. 表示された **16文字のパスワード** をコピーします(スペースは入れても入れなくても大丈夫です)。
   - これが **`SMTP_PASSWORD`** になります。
   - この画面を閉じると二度と表示されないので、すぐに次の手順で登録してください。

> 会社や学校の Google アカウントでは、管理者の設定によりアプリパスワードが使えないことがあります。その場合は個人の Gmail アカウントを使ってください。

## 5. GitHub Secrets に認証情報を登録する

トークンやパスワードは、**ファイルに書かず** GitHub の「Secrets(秘密の値を安全に保存する場所)」に登録します。

1. GitHub で自分のリポジトリを開きます。
2. 上部の **Settings** タブ → 左メニューの **Secrets and variables** → **Actions** を開きます。
3. **New repository secret** を押し、**Name** と **Secret** を入力して **Add secret** を押します。これを以下の項目ぶん繰り返します。

| Name(名前) | Secret(値) | 必要なとき |
|---|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | 3-3 でコピーしたチャネルアクセストークン | LINE通知を使う場合 |
| `LINE_USER_ID` | 3-2 でコピーした `U` から始まるユーザーID | LINE通知を使う場合 |
| `SMTP_USER` | 送信に使う Gmail アドレス(例: `yourname@gmail.com`) | メール通知を使う場合 |
| `SMTP_PASSWORD` | 4 で発行したアプリパスワード | メール通知を使う場合 |
| `EMAIL_TO` | 通知を受け取るメールアドレス(自分宛てなら `SMTP_USER` と同じでOK) | メール通知を使う場合 |
| `SMTP_HOST` | SMTPサーバー名 | 任意(登録しなければ `smtp.gmail.com`) |
| `SMTP_PORT` | SMTPポート番号 | 任意(登録しなければ `587`) |

- Name は **大文字・小文字も含めて表のとおり正確に** 入力してください。
- Gmail を使う場合、`SMTP_HOST` と `SMTP_PORT` は登録不要です。
- 未登録の項目があってもツールはエラーで止まりません。その通知手段がスキップされ、ログに警告が出ます。

## 6. 監視する銘柄を設定する(config.yaml)

リポジトリの `config.yaml` を編集します。GitHub 上で `config.yaml` を開き、右上の鉛筆アイコン(Edit)から直接編集して **Commit changes** で保存できます。

```yaml
notify:
  line: true            # LINE通知を使うなら true、使わないなら false
  email: true           # メール通知を使うなら true、使わないなら false
  email_always: false   # true: LINEが届いてもメールも送る / false: LINEが失敗したときだけメールを送る

stocks:
  - symbol: "7203.T"        # 銘柄コード(必須)
    name: "トヨタ自動車"     # 通知に表示する名前(省略可。省略すると銘柄コードが表示されます)
    threshold: 2500          # この値「以下」になったら通知(必須)
  - symbol: "AAPL"
    name: "Apple"
    threshold: 180
```

### 銘柄コード(symbol)の書き方

| 市場 | 書き方 | 例 |
|---|---|---|
| 日本株(東証) | 証券コード4桁 + `.T` | トヨタ自動車 → `"7203.T"`、ソニーグループ → `"6758.T"` |
| 米国株(NYSE / NASDAQ) | ティッカーをそのまま | Apple → `"AAPL"`、Microsoft → `"MSFT"` |

- わからないときは <https://finance.yahoo.com/> で銘柄を検索し、表示されるコード(例: `7203.T`)をそのまま使ってください。
- 英字を含む新しい形式の証券コード(例: `130A`)も、同様に `"130A.T"` と書きます。

### 閾値(threshold)について

- **その銘柄の現地通貨** で書きます。日本株は **円**、米国株は **ドル** です(通貨の換算はしません)。
- 現在値が閾値と **同じか、それより低い** ときに通知されます。
- 小数も使えます(例: `threshold: 179.5`)。

### 銘柄の追加・削除

- 追加: `- symbol: ...` から始まる3行のかたまりをコピーして、下に貼り付けて書き換えます。
- 削除: その銘柄の3行を消します。
- **行頭のスペース(字下げ)をそろえてください。** ずれると設定ファイルが読めなくなります。字下げには Tab ではなく半角スペースを使います。

## 7. 動作確認(手動実行・ローカル実行)

### 7-1. GitHub の Actions タブから手動実行する

1. リポジトリの **Actions** タブを開きます。
   - 初回は「Workflows aren't being run on this repository」などと表示されることがあります。その場合は緑色の **I understand my workflows, go ahead and enable them** を押します。
2. 左側の **Stock price check** を選びます。
3. 右側の **Run workflow** → **Run workflow** を押します。
4. しばらくすると実行結果が一覧に表示されます。クリックして **check** → **Check stock prices** を開くと、ログが見られます。

ログの例:

```
[INFO] 監視銘柄数: 2(基準日 2026-09-23 JST)
[INFO] トヨタ自動車 (7203.T): 現在値 2650.5 / 閾値 2500
[INFO] Apple (AAPL): 現在値 195.3 / 閾値 180
[INFO] 通知対象の銘柄はありません
```

**通知が届くか試したいとき** は、`config.yaml` の閾値を一時的に現在値より高い値(例: トヨタなら `99999`)にして手動実行してください。確認できたら元に戻すのを忘れずに。
(同じ日に同じ銘柄は1回しか通知されないため、もう一度試すには翌日まで待つか、`state.json` の中身を `{}` に書き換えてください。)

以降は 30 分おきに自動で実行されます。

### 7-2. 自分のパソコンで動かす(任意)

[Python 3.11](https://www.python.org/downloads/) をインストールし、このフォルダでターミナルを開いて以下を実行します。

**Mac / Linux**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

export LINE_USER_ID="ここにユーザーID"
export SMTP_USER="yourname@gmail.com"
export SMTP_PASSWORD="ここにアプリパスワード"
export EMAIL_TO="yourname@gmail.com"

python src/main.py
```

**Windows(PowerShell)**

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

$env:LINE_CHANNEL_ACCESS_TOKEN = "ここにトークン"
$env:LINE_USER_ID = "ここにユーザーID"
$env:SMTP_USER = "yourname@gmail.com"
$env:SMTP_PASSWORD = "ここにアプリパスワード"
$env:EMAIL_TO = "yourname@gmail.com"

```

## 8. 注意事項・既知の制約

- **株価データについて:** 株価の取得には `yfinance`(Yahoo Finance の **非公式** ライブラリ)を使っています。Yahoo Finance 側の仕様変更により、ある日突然動かなくなる可能性があります。また、データには遅延(日本株で約20分など)が含まれることがあります。投資判断は必ず証券会社などの正式な情報で確認してください。
- **実行タイミングについて:** GitHub Actions の定期実行は、指定した時刻ちょうどに動く保証がありません。混雑状況によって数分〜数十分遅れたり、まれに実行が飛ばされたりすることがあります。
- **市場が閉まっている時間も実行されます:** 現在の設定(30分おき)では、夜間や土日など市場が閉じている時間も実行されます(前回の終値で判定されます)。無駄を減らしたい場合は、`.github/workflows/check.yml` の `cron` を市場の時間に合わせて絞ってください。cron は **UTC(日本時間 −9時間)** で書きます。
  - 東証: 平日 9:00〜15:30(日本時間)
  - 米国市場: 平日 22:30頃〜翌5:00頃(日本時間。夏時間は 22:30〜翌5:00、冬時間は 23:30〜翌6:00)
  - 例: 東証の時間帯だけ 30 分おきに実行 → `cron: "*/30 0-6 * * 1-5"`(UTC 0〜6時台 = 日本時間 9〜15時台)
- **LINE の送信数上限:** LINE Messaging API の無料プラン(コミュニケーションプラン)は、**月あたりの送信数に上限**(執筆時点では月200通。最新の値は LINE の料金プランページで確認してください)があります。上限を超えると LINE 通知は失敗し、メール通知(有効な場合)に切り替わります。1回の実行で複数銘柄が該当しても 1 通にまとめて送るので、1通としてカウントされます。
- **GitHub Actions の利用時間:** Private リポジトリの無料枠は月 2,000 分です。30 分おきの実行(1回あたり約1分、1日48回)で月およそ 1,500 分前後を使います。他の用途でも Actions を使う場合や、実行間隔を短くする場合は注意してください。Public リポジトリなら無料で使い放題ですが、銘柄・閾値の設定が公開されます。
- **長期間放置すると定期実行が止まることがあります:** Public リポジトリでは、60日間リポジトリに更新(コミット)がないと定期実行が自動的に無効化されます。その場合は Actions タブに表示される案内から再度有効にしてください。
- **本ツールの対象外:** 暗号資産・投資信託・FX、「上回ったら通知」する上昇方向のアラート、複数人への通知には対応していません。

## 9. 困ったときは

| 症状 | 確認すること |
|---|---|
| LINE に通知が来ない | ① ボットを友だち追加しているか(3-4) ② Secrets の `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_USER_ID` の名前・値が正しいか ③ Actions のログに `LINE通知の送信に失敗しました: HTTP 401` などが出ていないか(401 ならトークン誤り、400 ならユーザーID誤りの可能性) |
| メールが来ない | ① Secrets の `SMTP_USER` / `SMTP_PASSWORD` / `EMAIL_TO` が登録されているか ② アプリパスワードを使っているか(普段のパスワードは不可) ③ 迷惑メールフォルダに入っていないか ④ `email_always: false` の場合、LINE が成功していればメールは送られません |
| ログに「価格を取得できなかったためスキップします」と出る | ① `symbol` の書き方が正しいか(日本株は `.T` 付き) ② Yahoo Finance 側の一時的な障害の可能性もあるので、次回の実行を待ってみる |
| ログに「未設定のため、LINE通知をスキップします」と出る | Secrets が未登録か、名前が間違っています(5 を参照) |
| 実行が赤い × で失敗している | ログを開いて確認してください。`config.yaml` の字下げずれなどで設定ファイルが読めないと失敗します。`state.json` のコミットで失敗している場合は、**Settings → Actions → General → Workflow permissions** が「Read and write permissions」になっているか確認してください |
| 同じ日に何度も通知が来る | 価格が閾値をまたいで上下している場合は、仕様どおり再通知されます(一度上回ってから再び下回ったとき) |
